
# PSYCH Wire & Cryptographic Protocol Specification

Version: 1.0.0-draft

Status: Normative

The `psych` protocol defines an end-to-end encrypted (E2EE), zero-knowledge message pipe between two peer nodes (`initiator` and `joiner`) mediated by an untrusted blind relay server.

---

## 1. Cryptographic Primitives

All implementations MUST use the following cryptographic primitives:

- **Key Agreement:** X25519 (ECDH over Curve25519, 32-byte public/private keys).
- **Key Derivation (KDF):** HKDF-SHA256.
  - Salt: Empty string / zero-length byte array.
  - Info string: ASCII byte sequence `psych-v1-session-key`.
  - Output length: 32 bytes (derived shared symmetric key $K$).
- **Authenticated Encryption:** ChaCha20-Poly1305 (RFC 8439 / AEAD).
  - Key: Derived key $K$ (32 bytes).
  - Nonce: 12-byte unique nonce per message.
- **Session ID (`sid`):** 16 bytes (32 hex characters), cryptographically secure random bytes generated by the initiator.

---

## 2. Pairing URI

The initiator constructs a URI encoded in the terminal QR code or transmitted out-of-band:

```
psych://pair?v=1&sid=<hex_session_id>&relay=<encoded_relay_url>&pub=<hex_initiator_x25519_pubkey>
```

### Parameters
- `v`: Protocol version integer. MUST be `1`.
- `sid`: 32-character lowercase hexadecimal string (16 raw bytes).
- `relay`: URL-encoded WebSocket endpoint (e.g., `ws%3A%2F%2F127.0.0.1%3A8080%2Fws` or `wss%3A%2F%2Frelay.example.com%2Fws`).
- `pub`: 64-character lowercase hexadecimal string (32 raw bytes of initiator's X25519 public key).

---

## 3. Relay Transport Layer (Untrusted)

The relay operates over standard WebSockets (`ws://` or `wss://`).

### 3.1 Endpoint
`GET /ws?sid=<hex_session_id>`

### 3.2 Relay Rules
1. A relay room is identified strictly by `sid`.
2. A room MAY contain at most **2** active WebSocket connections. If a 3rd connection attempts to join the same `sid`, the relay MUST reject the handshake with HTTP `409 Conflict` (or close with WS Status `4003 Room Full`).
3. The relay treats all payloads as opaque binary or text frames.
4. When a frame arrives from one peer, the relay forwards it unchanged to the other peer in the room.
5. If only one peer is connected, the relay MAY buffer up to 1 handshake message; all other non-handshake frames arriving before peer arrival SHOULD be discarded or error-signaled.
6. When both peers disconnect, the room and all ephemeral state MUST be deleted immediately.

Nonce Counter Strategy
To prevent nonce reuse without complex state machines:
 * Nonces are 12 bytes.
 * Byte 0 designates direction:
   * 0x00: Frames sent by Initiator.
   * 0x01: Frames sent by Joiner.
 * Bytes 1–3: Reserved (set to 0x00).
 * Bytes 4–11: Big-endian unsigned 64-bit integer counter, initialized to 0 and incremented by 1 for each frame sent by that party.
5. Encrypted Wire Envelope
All communication after the handshake MUST use this envelope sent as a WebSocket text (or binary) JSON frame:
{
  "seq": 0,
  "nonce": "<base64_encoded_12_byte_nonce>",
  "ciphertext": "<base64_encoded_ciphertext_and_poly1305_tag>"
}

6. Inner Payload Protocol (Decrypted Content)
When decrypted, the inner payload is UTF-8 encoded JSON:
{
  "id": "c7a8b6e2-...",
  "ts": 1793442400,
  "type": "text",
  "body": "Payload string or serialized data",
  "meta": {}
}

Defined Message Types
 * text: Plain UTF-8 text message (chat / clip).
 * file: Data payload. body contains Base64-encoded chunk, meta contains filename, size, and mime.
 * oauth_req (Reserved for Phase 2): body contains authorization URL.
 * oauth_resp (Reserved for Phase 2): body contains authorization code or redirected fragment.
 * ping / pong: Keep-alive probe.
